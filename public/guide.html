User Guide

From your first launch to running an honest, self-improving desk at full tilt.

The one rule: nothing trades real money until it has proven itself — and only you can flip that switch. Internalize paper-first, validated-or-it-doesn’t-trade, small size when live, and you’ll get the maximum out of Octopus without losing money the way most automation users do.

0The mindset

Octopus is different from every “AI trading bot” you’ve seen. It is research + disciplined automation, not a money printer. The honest truth, baked into the tool: most strategies have no edge. Octopus is built to find the rare ones that hold up and to tell you when something doesn’t work.

You hold the keys. It runs on your machine, trades your broker, never takes custody of your funds, and never goes live without your explicit confirmation.

1Install (5 minutes)

Requirements: Python 3.11+ and git. Runs on macOS, Linux, Windows, or a small VPS.

macOS / Linux — Terminal:

git clone https://github.com/Code-weaver1/octopus.git
cd octopus
./install.sh        # venv + deps + puts `octopus` on your PATH

If octopus isn’t found afterward, add the line install.sh prints to your ~/.bashrc.

Windows — use PowerShell, not cmd (the .sh script won’t run there):

git clone https://github.com/Code-weaver1/octopus.git
cd octopus
powershell -ExecutionPolicy Bypass -File install.ps1   # venv + deps + adds octopus to PATH

Then open a new terminal so PATH refreshes and run octopus setup. No need to change PowerShell’s execution policy — octopus runs through octopus.cmd, which handles that. To run it in the same session, call the .cmd from the folder: .\octopus.cmd setup (the bare .\octopus won’t work on Windows). Prefer Linux? Octopus also runs cleanly under WSL (Ubuntu) — follow the macOS/Linux steps inside WSL.

Uninstalling. Octopus lives in two places: the repo folder (launcher + .venv) and ~/.octopus (config + encrypted broker vault). The uninstaller removes the PATH entry and .venv but keeps ~/.octopus unless you ask for a full wipe.
# macOS / Linux
./uninstall.sh            # add --purge to also delete ~/.octopus
cd .. && rm -rf octopus   # then remove the folder

# Windows (PowerShell)
powershell -ExecutionPolicy Bypass -File uninstall.ps1   # add -Purge for a full wipe

2First launch & guided setup

The first time you run octopus (or octopus deck), a wizard runs automatically. Re-run any time with octopus setup. Five steps:

  1. Profile — pick a local handle.
  2. Risk disclosures — type I AGREE.
  3. OpenRouter API key — powers the AI features. Optional; rules, backtests, paper trading and dashboards all work without it.
  4. Connect a platform (optional) — MT5 / crypto / Alpaca. Start with demo/testnet/paper.
  5. Telegram (optional) — signal + audit alerts.

Everything lives under ~/.octopus/. Broker keys are encrypted at rest and never leave your machine.

3Your first 10 minutes (no money, no accounts)

You don’t need a broker — or even an API key. Open the live UI with octopus deck, then try:

💡 Run octopus signal validate on several markets and read the p-values. You’ll see most “strategies” don’t beat a coin flip — that scepticism is your edge. Trust only what clears the gate.

5The honesty engine

Three mechanisms make Octopus trustworthy — lean on them:

  • The validation gate — every strategy is judged against a random-entry control with matched time-in-market, out-of-sample, on full history. Can’t beat random → labelled UNVALIDATED, never sold as an edge.
  • The scoreboard — every signal logged and marked to market, including losers. No cherry-picking.
  • The auditor — a daily review that flags operational dangers and proposes fixes, but never changes anything itself.

The strategies, honestly: trend_ensemble, trend_breakout, donchian, regime_ladder have a validated edge on crypto (and are defensive elsewhere). ma_cross and rsi_meanrev have no edge anywhere — kept for transparency, never traded as edges.

6Going autonomous — on paper first

Octopus trades itself on a built-in paper simulator that needs no broker account.

octopus trade setup     # pick "Paper simulator — crypto"; it recommends trend_ensemble
octopus trade status    # the mandate + equity
octopus trade tick      # run one pass and see what it would do

Each tick: manages open positions first (cut losses / take profit), then looks for new entries, sizes them under your risk mandate (risk %, 20% max-position cap), and places a bracketed order with a protective stop.

Always-on safety: a per-account daily-loss cap, and a global kill switch — a file (~/.octopus/HALT) tripped by octopus trade halt, the deck’s k key, or the web button — that stops the loop from anywhere, even over SSH.

💡 Let a paper mandate run for weeks. The point isn’t a quick result — it’s building an honest forward track record before any real money is involved.

7Connecting real brokers (still demo/paper)

octopus link crypto     # Binance — use TESTNET keys
octopus link mt5        # Exness / FBS / IC via MetaApi — DEMO account
octopus link options    # Alpaca — PAPER keys

Octopus recommends the right engine per venue in octopus trade setup: crypto → trend_ensemble; stocks → trend_ensemble/regime_ladder; options → the Wheel. You can run multiple platforms at once, each with its own mode and strategy — prove it on all of them before risking a cent.

8The intelligence loop — maximum potential

A self-improving research pipeline that cannot overfit itself into the ground, because every machine-generated idea must pass the same validation gate.

PROPOSE   → an LLM brainstorms ideas        (octopus research --auto)
   gate ▸ must beat a random-entry control OUT-OF-SAMPLE
PAPER     → survivors forward-test themselves (they appear in Autopilot)
   gate ▸ stay profitable on paper for 4+ weeks
GRADUATE  → flagged "ready to consider for live" (🎓, Telegram'd to you)
   gate ▸ a human decision — only you can do this
LIVE      → small, daily-loss-capped, kill-switchable
  • octopus research BTC/USDT --auto — the LLM proposes; each idea is tested; only survivors are auto-promoted to a paper mandate. Most are rejected — that’s the gate working.
  • octopus improve --deep — an Opus-grade audit; proposes SAFE-NOW vs GATED fixes, never auto-applies.
  • On a VPS the daemon does this for you: a weekly research sweep and a daily audit that Telegrams high-severity risks.

💡 The LLM proposes; the validation harness disposes. That’s the whole safety model — and why you can let it get creative without it betting your account on a hunch.

9Going live (the one deliberate step)

octopus trade status                   # spot the 🎓 graduated candidate
octopus trade graduate research-<id>    # drafts a tiny, DISARMED live mandate
octopus trade enable live-<id>          # arm it deliberately

The graduate step drafts a disarmed tiny live mandate (small capital, 3% daily cap) and makes you type LIVE to confirm. It never auto-arms.

Live discipline: start with money you can afford to lose; keep the daily-loss cap tight and size small; know where the kill switch is. Only a thin edge has been validated (crypto trend) — treat live as a small-stakes experiment, not income.

10Run it 24/7 on a VPS

Put octopus trade run on a small Linux VPS (full details in VPS_RUNBOOK.md). With systemd:

# /etc/systemd/system/octopus-trader.service
[Service]
ExecStart=/home/YOU/octopus/octopus trade run --interval 300
Restart=always
WorkingDirectory=/home/YOU/octopus
User=YOU
sudo systemctl enable --now octopus-trader
journalctl -u octopus-trader -f      # watch it live

The daemon ticks every few minutes, audits itself daily, and runs a weekly research sweep — all honouring the kill switch you can trip from anywhere.

11The Wheel — options income (optional)

octopus link options             # Alpaca paper keys
octopus wheel plan AAPL          # preview the put it would sell
octopus wheel positions          # CSP → assigned → covered-call state
octopus wheel run F SOFI         # run a cycle (paper)

The covered call is always sold above your cost basis, so it never locks in a loss.

13A recommended weekly routine

  1. Monday — review. octopus trade status + octopus improve. Act on HIGH/MED audit findings; disarm anything unvalidated that’s armed.
  2. Let research run. The weekly sweep proposes + paper-tests new ideas; check the 🔬 Research tab for survivors.
  3. Watch graduations. When a candidate hits 🎓, decide deliberately whether to draft a tiny live mandate.
  4. Mid-week — glance, don’t fiddle. Open Autopilot or octopus web. Resist tweaking on a few days of noise — that’s how edges get curve-fit away.
  5. Always keep live size small, the loss cap tight, and the kill switch one keystroke away.
